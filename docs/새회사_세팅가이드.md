# 새 운송사 세팅 가이드 (회사별 별도 DB · 방식 B)

같은 프로그램 코드를 **회사마다 다른 Firebase 프로젝트(창고)** 에 연결해서 배포합니다.
돌캐(기존)는 아무 설정 없이 지금처럼 동작합니다. 아래는 **새 회사 1곳**을 추가하는 순서입니다.

> 예시: 회사명 `A운송`, 회사 키 `AUNSONG` (영문 대문자·숫자·_ 만)

---

## 1. Firebase 프로젝트 만들기 (약 15분)

1. https://console.firebase.google.com → **프로젝트 추가** → 이름 예: `kpflow-aunsong`
2. **Authentication** → 시작하기 → 로그인 방법 → **이메일/비밀번호** 사용 설정
3. **Firestore Database** → 데이터베이스 만들기 → 위치 **asia-northeast3 (서울)** → 프로덕션 모드
4. **Storage** → 시작하기 → 위치 서울
5. 프로젝트 설정(톱니바퀴) → 일반 → 내 앱 → **웹 앱 추가(</>)** → 나오는 `firebaseConfig` 값을 메모
6. (푸시 알림을 쓸 경우) 프로젝트 설정 → **클라우드 메시징** → 웹 푸시 인증서 → 키 쌍 생성 → 값 메모(VAPID 키)

## 2. 보안 규칙·인덱스 올리기 (본인 PC 터미널)

```
cd dispatch-app2
git pull origin main
firebase deploy --only firestore:rules,firestore:indexes -P kpflow-aunsong
```

**Storage 규칙은 복사해서 붙여넣기:** 돌캐 Firebase 콘솔 → Storage → **규칙** 탭 내용을 전체 복사 →
새 프로젝트 Storage → 규칙 탭에 붙여넣고 게시.
(저장소의 `storage.rules` 파일은 실제 운영 규칙과 달라서 그대로 올리면 사진 업로드가 막힙니다.)

> 처음 쓰다가 화면에 "**requires an index**" 오류가 나오면, 오류 메시지의 링크를 눌러 인덱스를 만들면 됩니다(몇 분 후 해결).

## 3. 서버 함수 올리기 (푸시 알림용, 선택)

- Firebase 요금제를 **Blaze(종량제)** 로 바꿔야 합니다.
- 구글시트 연동 함수(`backfillGsheet*`, `setupGsheetDailyLedger`, `syncDispatchToGoogleSheet`)는 **돌캐 전용**이라 빼고 올립니다.

```
firebase deploy -P kpflow-aunsong --only functions:notifyNewDispatch,functions:notifyDispatchDone,functions:notifyRedispatch,functions:notifyDispatchCanceled,functions:notifyDispatchDeleted,functions:notifyFleetDriverNewOrder,functions:notifyDispatcherOrderRejected,functions:notifyUnassignedUrgent,functions:notifyFleetOrderModified,functions:notifyFleetLateArrival,functions:cleanupOldAttachments,functions:notifyChatMessage,functions:sendPushNotification,functions:fuel,functions:lookupCompanyCode
```

## 4. Vercel 프로젝트 만들기 (약 10분)

1. https://vercel.com → **Add New → Project** → 같은 GitHub 저장소 `dispatch-app2` 선택
2. 프로젝트 이름 예: `kpflow-aunsong` (Root Directory는 비워둠 = 배차 프로그램)
3. **Environment Variables** 에 아래 값 입력 (1번에서 메모한 값)

| 이름 | 값 |
|---|---|
| `VITE_FIREBASE_API_KEY` | apiKey |
| `VITE_FIREBASE_AUTH_DOMAIN` | authDomain |
| `VITE_FIREBASE_PROJECT_ID` | projectId |
| `VITE_FIREBASE_STORAGE_BUCKET` | storageBucket |
| `VITE_FIREBASE_MESSAGING_SENDER_ID` | messagingSenderId |
| `VITE_FIREBASE_APP_ID` | appId |
| `VITE_DEFAULT_COMPANY` | `A운송` (회사명 — 가입 때 쓰는 회사명과 똑같이) |
| `VITE_FCM_VAPID_KEY` | (푸시 쓸 경우) VAPID 키 |
| `CALL24_API_KEY` 등 | (24시콜 연동 쓸 경우) 그 회사 계정 값 |

4. **Deploy** → 주소 생성(예: `kpflow-aunsong.vercel.app`). 도메인이 있으면 Settings → Domains 에서 연결
5. Firebase 콘솔 → Authentication → 설정 → **승인된 도메인** 에 위 주소 추가 (안 하면 로그인 안 됨)

## 5. 첫 관리자 만들기

1. 새 사이트 `/signup` 에서 **최고관리자 이메일(tjddnqkf@naver.com)** 로 가입 → 이 이메일은 자동으로 최고관리자
2. 고객사 관리자는 `/signup` 에서 가입 → 최고관리자 계정으로 로그인해 **승인**
3. 고객사 관리자가 이후 자기 직원·기사를 직접 승인

## 6. 기사앱 APK 만들기 (회사 전용)

1. GitHub 저장소 → Settings → Secrets and variables → Actions → **Variables** 탭 → New variable
   - 이름: `TENANT_AUNSONG`
   - 값(한 줄 JSON):
   ```
   {"API_KEY":"...","AUTH_DOMAIN":"...","PROJECT_ID":"...","STORAGE_BUCKET":"...","MESSAGING_SENDER_ID":"...","APP_ID":"...","DEFAULT_COMPANY":"A운송","FCM_VAPID_KEY":"..."}
   ```
2. GitHub → Actions → **Build Android APK** → Run workflow → `tenant` 칸에 `AUNSONG` → Run
3. 완료되면 Releases 의 **`driver-apk-AUNSONG`** 에 APK가 올라옵니다 → 그 회사 기사들에게 링크 전달

> 돌캐 기사앱은 지금처럼 main 푸시 때 `driver-apk-latest` 로 자동 빌드됩니다.

## 참고

- **공용으로 남는 것:** 배차마당(`cafe-site`)과 홈페이지(`landing-site`)는 모든 회사가 같이 쓰므로 돌캐 프로젝트에 그대로 둡니다.
- **지도·주소 API 비용:** Tmap·카카오 키는 지금 하나를 같이 씁니다. 사용량이 커지면 회사별 키로 나누는 것을 검토하세요.
- **업데이트:** 코드를 main 에 푸시하면 Vercel이 **모든 회사 사이트를 자동 재배포**합니다. 기사앱은 회사별로 6-2번을 다시 실행하세요.
