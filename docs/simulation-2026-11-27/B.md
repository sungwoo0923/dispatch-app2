- 기대: 거래처 · 상하차지 칸처럼 Enter = 첫 번째(강조된) 기사 선택. 지금은 키보드로 빠르게 입력하는 실무자가 "기사명만 있고 차량번호 없는" 오더를 만들게 됨(배차완료로 넘어가지 않거나 정산 때 기사 매칭 실패 위험).

### [확인됨] 운송관리자 vs 운송사무원 메뉴 차이
- 분류: 확인됨
- 사무원(이배차) 상단: HOME · 배차 · 운임 · 기사관리 · 거래처관리 · 매출관리(무반응) · 지입차관리 · 전자결재 · 회사관리
- 관리자(김운송) 상단: 위 + **관리자메뉴(5)**, 홈 게시판에 **관리자게시판** 추가. 배차 배지 숫자: 사무원 12~13 / 관리자 25~26(관리자는 전체 직원 기준으로 세는 듯 — 같은 오더를 보는데 숫자가 달라 헷갈림).
- 관리자메뉴: 회원 관리(승인 대기 5) · 연동 화주사 · 화주사 전송 · 화주사 문의 · 로그인 관리 · 초기 설정·튜토리얼. **운송관리자(물류운송팀 과장)가 경영지원팀 · 임원 · 영업팀 전 직원의 연락처 · 이메일 · 권한 · 인사발령 이력**을 봄. 직원 가입 승인도 운송관리자 몫(App 쪽 canApproveSignup 에 admin 포함). 실무에선 승인 · 인사정보는 인사 · 대표 쪽만 보는 게 일반적 → 운송관리자는 '물류운송팀' 사람만 보이게 하는 옵션 필요.
- 김운송이 이배차가 만든 오더(B-01) 운임을 바로 수정 가능 — 정상. 수정 패널 상단 "담당 이배차 · 배정 이배차 [담당자 변경]" 표시 좋음.

### [오류] 운송관리자 지입차관리 화면 콘솔 권한 오류
- 분류: 오류
- 중요도: 낮음
- 재현: 김운송 › 지입차관리(지입차량 관제) 진입 → 콘솔 `fleet_settings: FirebaseError: Missing or insufficient permissions.` 화면은 뜨지만 설정값을 못 읽음(담당 차량 0대).

### [개선아이디어] 실무자 입장 — 오더 1건 입력 클릭/입력 수(PC)
- 거래처(타이핑+Enter) → 상차지(타이핑+Enter, 담당자 2명이면 +1) → 하차지(타이핑+Enter) → 화물 수량 → 차종(타이핑+Enter) → 톤수 → 청구운임 → 기사운임(수수료 자동) → 지급방식(클릭 2) → 메모 → [저장] → 배차요청장 확인 [배차등록하기] → "등록되었습니다" [확인] = **입력칸 10개 + 클릭 약 6번**, Tab/Enter 위주로 마우스 없이 가능(좋음). 다만 마지막 '배차요청장' 미리보기 → [배차등록하기] → '등록되었습니다 [확인]' 단계가 매번 2번 더 눌러야 해서 하루 50건이면 100번. **"배차요청장 미리보기 건너뛰기" 옵션**과 등록 완료는 토스트로만 하면 좋겠음.
- 상차일 바꾸기: 달력 버튼 → 날짜 클릭(지난달이면 ‹ 한 번) — 날짜칸에 직접 `1031` 타이핑이 안 됨(버튼형). 키보드 입력 지원 아이디어.
- 지급방식 기본값이 '선택'(빈 값) — 거래처마다 거의 고정(계산서)이라 거래처 기본 지급방식을 기억해 채워 주면 클릭 2번 절약. 실제로 B-05 · B-10 처럼 빠뜨린 오더가 지급방식 '선택없음'으로 남음.
- 배차는 실시간배차현황 차량번호 칸에 차번 입력 → Enter → '기사 정보 확인'(확인 (배차완료)) — 3동작으로 빠르고 좋음. 다만 '배차 완료' 알림 토스트가 바로 아래 줄을 덮어 연속 배차 때 다음 줄 클릭이 한 번 씹힘(B-03 첫 시도 실패).
- 운임 수정은 줄 더블클릭 → 패널 → 스크롤 맨 아래 결제정보 → [수정 저장] → 확인 → (지급완료면 한 번 더). 표 칸에서 바로 고치는 '빠른 수정'이 운임엔 막혀 있어 4~5동작.

## 요약
가장 중요한 5개
1. **[오류 · 높음] 운송사 화면에 '오더 취소' 수단이 없음** — 우클릭 · 수정 패널 · 배차상태 어디에도 취소가 없고, 도움말이 말하는 '지급방식 → 취소'도 목록(PAY_TYPES, DispatchApp.jsx:274/2022)에 없음. 사무원은 삭제만 가능 → 취소 이력 · 정산 제외 규칙이 끊김(B-08 취소 못 함).
2. **[연동끊김 · 높음] 오더 입력에 '마감월' 칸이 없음** — 정산 · 매출은 마감월 기준(arCore monthOf)인데 운송 쪽에서 10/31 상차 · 11월 마감 같은 이월 건을 지정할 방법이 없음(B-06).
3. **[오류 · 높음] 오더등록 스마트검색 Enter = 기사 선택이 아니라 검색어가 기사명으로 들어감**(차량번호 · 전화 빈칸). 마우스 클릭만 정상. 숫자(차번 뒤 4자리)로는 검색도 안 됨.
4. **[보통] 운임 변경 연동** — 지급완료 오더는 "이미 지급한 오더예요 … 용차지급관리에 '지급 후 운임 변경 +15,000원'" 경고가 잘 뜸(B-11, D 확인 요청). 그러나 청구운임 변경 · 지급 전 변경(B-01)은 아무 표시 없이 덮어써지고 목록에 '금액 바뀜' 흔적이 없음. 사무원도 지급완료 오더 운임을 바로 바꿀 수 있음.
5. **[보통] 권한 노출** — 사무원에게 매출관리 메뉴가 보이지만 눌러도 무반응, 대신 홈 대시보드에서 회사 이번 달 · 올해 매출 · 수익 · 담당자별 순위를 그대로 봄. 운송관리자는 관리자메뉴에서 전 부서 직원 연락처 · 권한 · 인사발령 이력을 보고 가입 승인까지 함. 지급방식 · 상차방법 목록 편집/삭제도 사무원에게 열려 있음.

그 밖: 기사 전화번호 중복 경고 없음, 신규 기사 등록에 차종 · 구분 칸 없음, 거래처 칸이 너무 좁음, 기본거래처 검색 결과에 엉뚱한 줄 섞임, 과거 상차일 · 청구 0원 무경고, 특수운임이 기본운임에 합산돼 내역이 목록 · 엑셀에 안 보임, 일괄복사 기본 날짜=원본과 같은 날 + 브라우저 confirm, 엑셀 파일명 'download' · 전화번호 형식 섞임, 미배차/배차중 용어 혼용.
환경 제약: 지도 · 거리계산 · 매출관리 비밀번호 서버(cloudfunctions) 호출 차단. 같은 이배차 계정을 성능 측정(H)이 PC로 계속 써서 4~5번 강제 로그아웃됨.

실무자 한 줄 소감: "오더 입력 · 배차(차번 Enter) 자체는 키보드만으로 빠르고 예상운임 · 상하차지 자동채움이 정말 편한데, **취소 · 이월(마감월) · 운임 변경 흔적**처럼 경리랑 맞물리는 부분이 운송 화면에서 비어 있어서 결국 메모와 전화로 따로 알려야 할 것 같아요."
